# Evaluation

What PharmGuard's evaluation measures, every number it has produced, and what it doesn't measure. Every number
below was produced by running code in this repository and is regenerated by the command named next to it. Each
names its data build:
- the **synthetic sample** (85 hand-written interaction records; what CI checks);
- the real **public** build (RxNorm Current Prescribable 2026-09-08, Drugs@FDA brand names, the DDInter bulk
  download of 2024-05-21 and SIDER 4.1; 169,673 interaction records; what the live app serves);
- the real **research** build (public + TWOSIDES; aggregate numbers only, because TWOSIDES has no license).

Unmeasured values are "—". Every results file records the sha256 of its build's `provenance.json`, and an opt-in
test (`pytest --run-realdata`) fails if a committed result doesn't match the build on disk.

## Definitions

- **Pair.** Two distinct canonical drugs (RxNorm ingredient names) from one input list. A list of *n* drugs has
  *n(n−1)/2* pairs; PharmGuard checks every one.
- **Curated record.** A DDInter row for the pair, with its grade: Major, Moderate, Minor, or "not graded"
  (DDInter lists the pair without a grade).
- **Statistical signal.** A TWOSIDES row (research build) or a FAERS signal: a reporting pattern with a PRR,
  never a severity.
- **Declared.** Named in the report's coverage section: an unresolved or ambiguous input, or a pair with no
  curated record ("No Curated Interaction Data").
- **Silent.** A pair or input that is neither reported nor declared. The design goal is that nothing is ever
  silent.
- **Clinical claim.** A report line that states something clinical about specific drugs (src/verification);
  titles, headings, notices and the disclaimer are not claims.
- **Recall** against a reference: reference interactions PharmGuard reports ÷ reference interactions.
  **Under-triage:** reported with a lower grade than the reference's minimum.
- **Faithfulness:** claims an LLM judge rates "supported" by their cited records ÷ claims judged.

## Test cases

`src/evaluation/test_cases.py` has 57 cases:
- 48 across 12 clinical groups (geriatric, textbook interactions, edge cases, mental health, cardiology,
  endocrine, infectious disease, oncology-adjacent, pain, respiratory, GI, a 10-drug profile);
- 9 brand-name and look-alike cases (LA-*), which test normalization only.

The 37 hand-labelled `known_interaction_pairs` name each case's headline interaction. They are partial by design,
so precision against them is a lower bound. Label changes need the owner's approval and are listed in
docs/LABEL_CHANGES.md (2026-09-29: EDG-03's label removed, END-02 moved to insulin glargine, LA-09 added).

## 1. Independent evaluation

The hand labels were written by the same person as the system, and the internal-consistency check (ground truth
from the same table the retriever uses) is 1.0 by construction. The checks in this section use references
PharmGuard doesn't read.

### 1a. Graceful degradation: holdout

`python scripts/eval_holdout.py --profile public|research`. 10% of the DDInter pairs (seed 20260928, sampled by
pair) are removed from a copy of the build. Each removed pair is then run on its own. **This is a
graceful-degradation test, not a retrieval-quality test.** It shows what a user sees when the curated source has
a gap, not how many real interactions DDInter lacks.

| Held-out pairs (16,966) | public | research |
|---|---:|---:|
| declared as no data | 16,966 (100%) | 11,534 (68.0%) |
| recovered from another source (TWOSIDES signals) | 0 | 5,432 (32.0%) |
| unresolved / input rejected | 0 / 0 | 0 / 0 |
| **silent** | **0** | **0** |

On the research build, 388 of the 2,715 held-out Major pairs come back only as TWOSIDES signals, which carry no
severity: the pair is still reported, but it is no longer labelled Major.

### 1b. FDA labeling as a reference set

`data/validation/reference_interactions.csv` has 41 pairs: 31 well-established interactions and 10 negative
controls. `python scripts/verify_reference_labels.py` checks each automatically against current FDA labeling from
openFDA's drug label API (public domain, fetched 2026-09-29):
- **Label choice:** each drug's label is a single-ingredient one, NDA first, then the most recent.
- **Search:** the label is searched for the other drug by generic, salt or brand name in Boxed Warning,
  Contraindications, Warnings and Precautions, and Drug Interactions.
- **Classification:** the wording around each match is classified as contraindicated, avoid / not recommended,
  monitor / adjust, mentioned without guidance, or not mentioned.
- **Recorded per row:** the label's set ID and version, the section, a snippet and the fetch date.

**The wording classification is heuristic** (keyword rules in `src/evaluation/label_evidence.py`), and the rules
were refined by reading these same labels, so it isn't independently validated. An expected interaction counts as
verified only if a label gives guidance (monitor / adjust or stronger). A negative control counts as verified
when neither label names the other drug, which is **only weak evidence** of no interaction. Rows the labels don't
settle (8: for example a drug named only as a class member, or no single-ingredient label for ethinyl estradiol)
are excluded and counted.

`python scripts/score_reference_set.py` (public build, deterministic):

| | Result |
|---|---|
| Rows / scored / excluded as unclear | 41 / 33 / 8 |
| Verified interactions (label: contraindicated 11, avoid 1, monitor / adjust 11) | 23 |
| Detected with a DDInter grade | 23 of 23 (recall 1.000) |
| Under-triage (DDInter grade below the label's mapped minimum) | 0 of 23 |
| Silent misses | 0 |
| Negative controls (neither label names the other drug) | 10: all 10 are DDInter listings **without a grade**; none is graded |
| FDA label vs DDInter: same grade, with contraindicated or avoid mapped to Major and monitor / adjust to Moderate | 13 of 23 (0.565). DDInter is higher in the other 10 (Major where the label says monitor / adjust), never lower |
| DDInter vs Drugs.com | — (3 pairs picked for a manual lookup: simvastatin + clarithromycin, warfarin + amiodarone, atorvastatin + lisinopril) |

Read with care: 23 pairs, chosen as well-established interactions, is a small and easy set. Recall 1.000 on it
says the obvious interactions are there, not that coverage is complete. The negative controls show that DDInter
lists many pairs without a grade even when neither label mentions the other drug. The report keeps those under
their own heading, "Listed by DDInter without a severity grade".

### 1c. Can a PRR stand in for a curated grade?

`python scripts/eval_severity_agreement.py` (research build, aggregate only). 23,549 pairs have both a DDInter
grade and a TWOSIDES signal. The pair's tier comes from its highest-PRR event. The pairs were split 50/50 by pair
(seed 20260928); thresholds were tuned on the calibration half only, maximising linear-weighted κ.

| Test half (11,775 pairs) | Accuracy | Macro-F1 | Linear-weighted κ | Spearman (tier) | Spearman (PRR) |
|---|---:|---:|---:|---:|---:|
| current tiers: Moderate ≥ 4, Major ≥ 10 | 0.198 | 0.130 | 0.002 | 0.005 | 0.032 |
| tuned on the calibration half: Moderate ≥ 8.57, Major ≥ 100 | 0.611 | 0.340 | 0.019 | 0.014 | 0.032 |
| baseline: always Moderate | 0.757 | 0.287 | 0.000 | — | 0.032 |

PRR carries almost no information about DDInter's grade, even after tuning. That is why PharmGuard never puts a
severity word on a TWOSIDES signal: they appear in their own section with PRR and co-report count only.

### 1e. FAERS signal thresholds

For pairs with no curated record, the optional FAERS lookup (`src/retrieval/faers_stats.py`) computes PRR, ROR
with a 95% CI and a Yates χ² from openFDA counts. It shows a signal only if all of these hold:
- the Evans criteria (PRR ≥ 2, χ² ≥ 4, at least 3 reports);
- the ROR's lower bound is above 1;
- the pair's event rate is at least twice each drug's rate in reports without the other.

The rest are counted as suppressed. Unit tests use hand-computed 2×2 tables.

`python scripts/demo_faers_signals.py` (live openFDA, 2026-09-28; results/faers_signal_demo.md):
- **Surfaced:** simvastatin + clarithromycin, rhabdomyolysis (PRR 65.28, ROR 74.79, 95% CI 65.32–85.63).
- **Suppressed:** metformin + lisinopril, diarrhoea. It passes the Evans criteria (PRR 2.11, χ² 2040.1, ROR
  lower bound 2.12), but metformin alone has the same rate (0.0647).
- **Surfaced, but a likely artifact:** simvastatin + clarithromycin, "macular degeneration" at PRR 192.50. The
  thresholds can't catch every reporting artifact.

## 2. Report checks

### 2a. The checker (`src/verification`)

`validate_report(report, evidence)` parses the report into claims, reads each claim's `[SOURCE:RECORD_ID]`
citations and drug mentions, and checks the claim against the records it cites. It is the runtime guardrail too:
an LLM draft that fails is never shown.

| Code | Catches |
|---|---|
| `PHANTOM_CITATION` / `MISATTRIBUTED_CITATION` | cited ID not in the evidence / belongs to another pair |
| `SEVERITY_MISMATCH` | a section or tier word that differs from the curated record |
| `SEVERITY_ON_STATISTICAL_SIGNAL` | a severity word on a TWOSIDES signal, or a signal under a severity heading |
| `NUMERIC_MISMATCH` | a PRR, co-report or FAERS report count that differs from the record |
| `EVENT_MISATTRIBUTION`, `UNSUPPORTED_MECHANISM`, `UNSUPPORTED_POPULATION` | an event, mechanism (isoform-aware) or population not in the cited record |
| `FAERS_AS_CURATED` | a FAERS signal cited outside its unvalidated section |
| `UNCITED_CLAIM` | a clinical claim with no citation |
| `OMITTED_INTERACTION`, `OMITTED_MAJOR`, `MISSING_HIDDEN_COUNT` | a pair with records never cited; a curated Major never cited; hidden signals not stated as "+N more not shown" |
| `MISSING_NO_DATA_DECLARATION`, `CONFLATED_ABSENCE`, `MISSING_UNRESOLVED_DECLARATION`, `MISSING_DISCLAIMER` | a gap not declared, or absence written as safety; the disclaimer not present exactly once |

Metrics (micro-averaged): semantic hallucination rate (clinical claims with a fabrication finding ÷ clinical
claims), uncited-claim rate, citation validity, pair and Major omission rates, and completeness (no-data pairs
declared ÷ no-data pairs).

**The checker is a lower bound.** Mechanisms, events and populations are matched with hand-written lexicons
(`src/verification/lexicon.py`). A fabrication worded outside them passes: all 5 blind-spot probes are missed
("hepatic enzyme blockade", "patients over 80", "risk roughly triples", "muscle breakdown", "lowering digoxin
levels"). The LLM judge (3) is the planned second layer.

### 2b. Validating the checker (`python scripts/validate_checker.py [--profile public|research]`)

| Report set | sample | public | research |
|---|---:|---:|---:|
| 57 evaluation cases: reports / clinical claims / findings | 57 / 124 / 0 | 57 / 239 / 0 | 57 / 931 / 0 |
| random 4-drug lists (seed 7): reports / claims / findings | — | 200 / 239 / 0 | 200 / 376 / 0 |
| hard names (comma, parenthesis, > 30 characters) | — | 27 / 153 / 0 | 44 / 730 / 0 |

Sensitivity: 14 fault types are injected into synthetic fixture reports in template and prose styles. They
include the canonical case: a record says P-glycoprotein and the report claims CYP3A4, with the same, real
citation. Every injected instance raises its expected code. This shows each check works on the fault it targets.
It isn't an estimate of how many real LLM errors are caught, because the injected terms come from the checker's
own lexicons (results/checker_validation.md).

## 3. LLM path and the judge

`python scripts/run_llm_eval.py` produces every real-model number in one run: first-draft pass rate, recovery on
retry, fallback rate, tokens per report, top finding codes, checker metrics on first drafts and on shown reports,
judge faithfulness, and the deterministic-vs-LLM comparison. `--plan` makes no calls and prints the call budget.
On the public build that is 57 to 114 generation calls plus about 239 judge calls per provider.

**The judge.**
- **What it sees:** each cited clinical claim alone, with only the records it cites. It returns
  `{"verdict": "supported" | "unsupported" | "contradicted", "rationale"}`.
- **Prompt:** `src/evaluation/prompts/judge_v1.txt`, sha256
  `ce2d0157ac2688a44174b1bc24135788e93303d53ecccbab9bf1f8ea23df41fa`.
- **Provider:** it must be a different provider from the generator unless `--allow-same-provider-judge` is
  passed, and results disclose which was the case.
- **Audit:** a seeded 20% of judged claims is exported blind (`results/judge_audit_<profile>.csv`, verdicts
  hidden). `python scripts/score_judge_audit.py` reports percent agreement and Cohen's κ.

### First run: gemini-3.5-flash-lite on the synthetic sample (29 September 2026)

**Sample-only.** It ran on the 85-record synthetic sample, not the public build, so no DDInter data went to a
free-tier service. The numbers describe a model on this harness, not PharmGuard's accuracy on real drugs.

- **Model:** Google `gemini-3.5-flash-lite` on the free tier (a key from a project with billing disabled; 253

- **The same model generated the reports and judged them.** A same-provider judge may be lenient with its own

What this does and doesn't show:
- **The guardrail did its job.** Every failing first draft was either fixed on the retry or replaced by the
  template, so no report that failed the checker was shown. The findings on rejected drafts were a severity
  word attached to a statistical signal (3) and uncited claims (2).
- **The judge didn't wrongly flag correct claims.** It rated all 124 template claims supported; those restate

- **The judge's sensitivity is unmeasured: —.** It was only shown claims that had already passed the checker. So
  "123 of 123 supported" can't say how often it would catch a fabrication. Measuring that needs judge runs on
  known-bad claims (for example the checker's injected faults) and the human audit.
- **LLM-mode latency: —.** The run spaced calls 5 s apart for the free tier, so its timings measure the spacing.

## 4. Orchestration: trajectory evaluation

`python scripts/eval_trajectory.py --fault-suite --seeded-bugs --min-invariant-pass 1.0 [--profile ...]`. It runs
offline with scripted fake LLMs and is CI's gate.
- **Step scoring:** every step (normalize, plan, retrieve, route, finalize) of every case must be right.
- **Fault suite:** scripted drafts for 15 scenarios: clean, with and without FAERS; transient or permanent errors; a fabricated mechanism
  once or always; an omitted Major; absence stated as safety; a phantom citation; a severity flip; an uncited
  claim; a severity word on a signal; a different fault on the retry; the retry repeating the rejected draft.
- **Invariants:** 11, checked on every run and computed independently of the graph's own claims.
- **Seeded bugs:** six orchestration bugs that each must break at least one invariant.

## Limitations

- **Lexicon checks are a lower bound.** The checker misses fabrications worded outside its lexicons (2a). The
  LLM judge has run only on the synthetic sample, with the same model judging its own reports, and its ability to
  catch errors is unmeasured (3).
- **Pairwise only.** Every check is per pair. A pattern that needs three drugs at once, such as an NSAID + ACE
  inhibitor + diuretic, is not flagged as a combination.
- **Severities are DDInter's.** PharmGuard copies DDInter's grade and doesn't reconcile references. References
  disagree widely. Kontsioti et al. compared the BNF, the French Interactions Thesaurus and Micromedex: only
  6,970 interactions appeared in all three, 78.04% of drug pairs were listed by just one, and severity ratings
  agreed poorly (Br J Clin Pharmacol 2022; https://www.ncbi.nlm.nih.gov/pmc/articles/PMC9545693/). Against FDA
  labeling, DDInter's grade is higher in 10 of 23 verified pairs (1b).
- **The live data is the public build.** No TWOSIDES, so no statistical signals on the live site; FAERS is off by
  default.
- **References are small and partly heuristic.** The FDA-label reference is 33 scored rows with a keyword-based
  wording classification tuned on those same labels. The hand labels are partial.
- **No mechanism text.** The DDInter bulk files have none, so reports can't say why a pair interacts.
- **No clinician review yet (5), and LLM numbers on the synthetic sample only (3).**
